# TradeLedger UI/UX audit · 21 November 2026

This report records the interface at `834f87f`, before the fixes on `fix/ui-ux-audit`. The screenshots show the original behavior.

**Follow-up verification.** After code review, the fix branch passed 1,172 unit and integration tests and all 137 Chromium tests. Regression cases cover changed decision previews, both orders of a mixed-validity import batch, evidence and history beyond page one, report drafts, model pricing, and 375px layouts at doubled text size. The production smoke test also verified database migration, startup and shutdown.

The highest-risk findings were in decision preview and strategy evidence. In a temporary journal, changing an exclusion from one CSV to another still submitted the first file. Opening a BIDU stock strategy showed two AXON option lots. In a separate 110-execution journal, a trade on Transactions page 2 had a working source link, but opening that trade's strategy showed a dash for the same source.

## Scope and evidence

Reviewed the React web app at commit `834f87f` using UI/UX Pro Max, with emphasis on accessibility, interaction, responsive layout, feedback, navigation, and financial data presentation. The [earlier page audit](2026-11-21-page-ux-audit.md) records fixes already on this branch.

- **Browser** means observed in the current production build with Playwright Chromium and disposable local journals. Checks covered empty and populated pages, 1280 × 800 desktop, 375 × 812 phone, 768 × 1024 tablet, and 812 × 375 landscape. Tablet and landscape used dark mode. Additional checks used reduced motion, doubled root text size, a failed model request, malformed CSV, a configured model, and a 110-execution journal with two currencies.
- **Source** means traced through the current components and relevant data handlers. The existing **117 Chromium end-to-end tests passed**, including streaming, interactive connections, campaign reporting, proposal acceptance, exports, print layout and reset confirmation. Some tests use controlled responses. Physical devices, screen-reader speech output and production-sized performance were outside the measured coverage.
- **High** means the interface can cause a wrong decision, hide material evidence or lose information. **Medium** means a task requires avoidable searching, re-entry, or a workaround. Screenshots contain synthetic records.

## Visual and accessibility checks

- The shared typography, right-aligned ledger figures, and restrained use of danger and gain/loss colors support scanning. Primary text against the page background measured **16.51∶1 in light mode and 15.72∶1 in dark mode**. Muted text measured **7.01∶1 and 8.59∶1** respectively. These are measurements of the shared body color pairs. [Theme tokens](../../src/web/styles.css#L27)
- Keep visible keyboard focus, the skip link, route-change focus, keyboard-scrollable ledger tables and the reduced-motion rules. Prioritize the timed approval announcement, identifying column placement and tablet navigation before palette changes. [App shell](../../src/web/App.tsx#L147) · [Table region](../../src/web/components.tsx#L75) · [Motion rules](../../src/web/styles.css#L628)
- For the next regression pass, exercise workflows that cross pages or reload data. The smallest valuable set is changing a field after preview, opening an execution past page 1 from both entry points, mixing valid and invalid imports, changing a report period with a draft, disabling a priced profile, and rejecting proposals then reopening the run. Each checks the state the trader sees after the action.
